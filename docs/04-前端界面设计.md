# 04 · 前端界面设计

> 前端定位为"简单界面"：**原生 HTML5 + CSS3 + JavaScript 单页应用**，无框架、无构建工具，经 Go `embed.FS` 随服务一起托管，浏览器直接访问 `http://127.0.0.1:8080/` 即可使用。

## 1. 设计原则

| 原则 | 说明 |
| --- | --- |
| 极简 | 三个静态文件（html/css/js），零依赖、零构建 |
| 单页 | 顶部导航 + 内容区切换，不刷新页面 |
| 直观 | 每个功能面板一个卡片，操作按钮 + 结果区 |
| 数据直读 | 全部数据来自 REST API，前端不做业务计算 |
| 可演示 | 内置"模拟写入"表单，方便演示哈希链效果 |

## 3. 六大功能面板

### 3.1 总览（Overview）

- 服务状态灯（健康检查：绿=ok / 红=异常）；
- 统计卡片：总条目数、活跃条目数、归档条目数、归档批次数；
- 链头信息：当前 `seq` 与 `head_hash`（等宽字体，支持一键复制）；
- 最近一次完整验证的状态与时间。

数据源：`GET /api/v1/health`、`GET /api/v1/stats`、`GET /api/v1/entries/head`。

### 3.2 记录写入（Write）

- 表单：操作人（actor）、动作（action 下拉 + 自定义）、目标（target）、详情（detail，JSON 文本框）；
- "写入"按钮 → `POST /api/v1/entries`；
- 成功后展示返回的条目 JSON，**高亮展示新条目的 `seq`、`prev_hash`、`hash`**，直观体现哈希链的衔接；
- 失败展示错误码与消息。

### 3.3 记录列表（List）

- 过滤区：actor / action / target / 时间区间 / 是否包含归档；
- 分页表格：seq、时间、操作人、动作、目标、哈希摘要（悬停显示完整哈希）；
- 行内操作：查看详情（完整 JSON）、"上下文"跳转到追溯面板。

数据源：`GET /api/v1/entries`。

### 3.4 追溯分析（Trace）

- 查询区：同列表过滤条件；
- 结果表格 + "导出审计报告"按钮（`GET /api/v1/trace/report`，下载 JSON）；
- 上下文视图：输入条目 ID 与 radius → 展示该条目及前后条目的时间线，前后条目的 `prev_hash/hash` 衔接关系以 ✓/✗ 标记显示。

数据源：`GET /api/v1/entries/:id/context`。

### 3.5 完整性验证（Verify）

- 模式选择：全链 / 区间 / 链头 / 抽样（区间与抽样显示额外输入项）；
- "执行验证"按钮 → `POST /api/v1/verify`；
- 结果展示：
  - 大字状态徽章（✅ OK 绿色 / ❌ 异常红色）；
  - 验证报告 JSON（含 `break_seq`、`break_reason`、耗时、检查数）；
  - 归档批次衔接明细表。

### 3.6 归档管理（Archive）

- "立即归档"按钮 → `POST /api/v1/archive`；
- 归档任务状态卡片（运行中标志、上次运行时间、上次错误）；
- 批次列表表格（批次号、seq 区间、条目数、链头哈希、时间）；
- 行内"导出批次" → 下载该批次 JSON（清单 + 条目）。

数据源：`GET /api/v1/archive/status`、`GET /api/v1/archive/batches`、`GET /api/v1/archive/batches/:no`。

## 4. 交互流程

1. **首次加载**：并行请求 health/stats/head，渲染总览面板，设置状态灯；
2. **面板切换**：点击左栏导航，JS 切换内容区（`display` 切换），进入面板时按需拉取数据；
3. **写入演示**：填表 → 提交 → 渲染新条目 → 自动刷新统计与链头；
4. **验证流程**：选模式 → 提交 → 渲染徽章与报告 → 提示"验证动作已入链（seq=…）"；
5. **错误提示**：任何 API 失败，统一在结果区展示红色错误条（含 code/message）。

## 5. 与后端 API 映射

| 前端功能 | API |
| --- | --- |
| 总览 / 状态灯 | GET /api/v1/health, /stats, /entries/head |
| 记录写入 | POST /api/v1/entries |
| 记录列表 | GET /api/v1/entries |
| 上下文回溯 | GET /api/v1/entries/:id/context |
| 追溯报告导出 | GET /api/v1/trace/report |
| 完整性验证 | POST /api/v1/verify |
| 手动归档 | POST /api/v1/archive |
| 归档状态 / 批次 | GET /api/v1/archive/status, /archive/batches, /archive/batches/:no |

## 6. 文件结构与代码要点（设计描述）

```
web/
├── index.html    # 页面骨架：导航、六个面板容器、模板区
├── style.css     # 深色系简洁样式：卡片、表格、徽章、状态灯、响应式
└── app.js        # 全部逻辑：fetch 封装、面板渲染、表单提交、JSON 展示
```

| 文件 | 内容要点 | 规模预估 |
| --- | --- | --- |
| index.html | 导航 + 面板容器 + 空态模板；引用 style.css / app.js | ~180 行 |
| style.css | CSS 变量配色、卡片/表格/徽章/表单样式、状态灯动画 | ~260 行 |
| app.js | `api(path, opts)` 封装、`render*` 系列函数、路由切换、轮询归档状态（5s） | ~350 行 |

**JS 要点（设计描述）**：

- `api()`：封装 `fetch`，统一 `Content-Type`、错误体解析（`error.code/message`）、401 提示；
- `state`：当前面板、分页参数、链头缓存；
- 哈希展示：等宽字体 + 前 8 位摘要 + 悬停完整值（不截断真实数据）；
- 验证徽章：`status==="ok"` → 绿 ✓，否则红 ✗ + 断点信息；
- 归档状态轮询：进入归档面板后每 5s 拉取一次 `archive/status`，`running=false` 时停止。

> 前端文件不计入 Go 代码行数约束（docs/02 §5.2），但计入"简单界面"交付要求。
