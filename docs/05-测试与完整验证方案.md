## 1. 测试目标

| 目标 | 说明 |
| --- | --- |
| T1 | 哈希链核心算法正确（追加/哈希/验证各模式） |
| T2 | 篡改可被检测（hash_mismatch / link_broken / head_mismatch） |
| T3 | 归档不破坏链，批次清单正确 |
| T4 | 迁移按版本执行且可重复部署 |
| T5 | API 行为符合 docs/03 规格 |
| T6 | 完整验证端到端通过 |

## 2. 测试分层与策略

```
┌─────────────────────────────────────────────┐
│  E2E 端到端（演练脚本 verify_e2e.sh 或 Go 测试） │  ← 最高层，验证整条业务链
├─────────────────────────────────────────────┤
│  集成测试（internal/api 用 httptest + SQLite） │  ← HTTP 层行为
├─────────────────────────────────────────────┤
│  单元测试（chain / store / service / worker）  │  ← 算法与逻辑
└─────────────────────────────────────────────┘
```

- 单元测试**不依赖真实 SQLite**：`store` 提供内存实现（docs/02 #6）用于 service 层测试；SQLite 行为单独用临时文件测试；
- 集成测试使用 `httptest.NewServer` + 临时 SQLite 文件（`t.TempDir()`）；
- 端到端演练以真实二进制 + 真实库执行，作为交付验收动作。

## 5. 端到端验证脚本（篡改演练）

以 shell 脚本 `scripts/e2e_verify.sh`（设计示意）执行，验收标准为**全部步骤通过**：

```bash
#!/usr/bin/env bash
# 1. 启动服务（临时库）
./auditlog-server -db /tmp/audit_e2e.db -addr 127.0.0.1:18080 &
sleep 1

# 2. 写入 1500 条关键操作（循环调用 POST /entries）
for i in $(seq 1 1500); do
  curl -s -X POST .../api/v1/entries \
    -d "{\"actor\":\"user$((i % 10))\",\"action\":\"data_modify\",\"target\":\"rec:$i\"}"
done

# 3. 触发归档（阈值 1000 → 应产生批次）
curl -s -X POST .../api/v1/archive && sleep 2
#    断言：archive/status 中 last_batch_no >= 1

# 4. 完整验证 → 必须 ok
curl -s -X POST .../api/v1/verify -d '{"mode":"full"}'
#    断言：status == "ok"

# 5. 模拟篡改：UPDATE 一条主库条目的 target
sqlite3 /tmp/audit_e2e.db "UPDATE audit_entries SET target='TAMPERED' WHERE seq=952;"

# 6. 再次完整验证 → 必须 hash_mismatch 且 break_seq=952
curl -s -X POST .../api/v1/verify -d '{"mode":"full"}'
#    断言：status == "hash_mismatch" && break_seq == 952

# 7. 停止服务，检查迁移版本与批次导出
kill %1 && wait
echo "E2E PASSED"
```

> 该脚本在编码完成后实现于 `scripts/e2e_verify.sh`（或等价 Go 测试 `e2e_test.go`），文档阶段仅作方案描述。

## 6. 完整验证流程与报告样例

**流程**（对应 docs/01 §11）：

1. 锁定写入（或链头快照）→ 采用链头快照，不阻塞写入；
2. 合并读取主库 + 全部归档批次条目（按 seq 升序）；
3. 逐条执行哈希重算与 prev_hash 衔接检查；
4. 校验批次衔接（批次 head_hash == 下一段首条 prev_hash）；
5. 验证动作本身写入审计链（`action="verify"`）；
6. 输出结构化报告。

**报告样例**（完整验证，全部通过）：

```json

  "status": "ok",
  "checked_entries": 12501,
  "start_seq": 1,
  "end_seq": 12501,
  "break_seq": 0,
  "break_reason": "",
  "head_hash": "ab12cdef…",
  "archives_checked": 3,
  "archives": [
    {"batch_no": 1, "start_seq": 1,    "end_seq": 8000,  "head_hash": "c3f2…", "linked": true},
    {"batch_no": 2, "start_seq": 8001, "end_seq": 12000, "head_hash": "9f86…", "linked": true},
```

## 7. 覆盖率与质量门禁

| 门禁 | 标准 |
| --- | --- |
| 单测覆盖 | 核心包（chain / store / service）行覆盖率 ≥ 80% |
| 必过用例 | 3.1 全部 + 4 中 TestVerifyEndpoint / TestPostEntry |
| 端到端 | `scripts/e2e_verify.sh` 全绿 |
| 静态检查 | `go vet ./...` 无告警；`gofmt` 无 diff |
| 行数验收 | `find . -name '*.go' ! -name '*_test.go' | xargs wc -l` 合计 ∈ (2000, 2200) |
| 文件数验收 | 同命令统计文件数 ∈ (20, 25) |
