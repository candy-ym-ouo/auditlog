## 1. 分层架构

```
┌────────────────────────────────────────────────────────────┐
│                       前端界面 (web/)                       │
│       原生 HTML/CSS/JS，经 embed.FS 由 Go 服务托管           │
└──────────────────────────┬─────────────────────────────────┘
                           │ HTTP (JSON)
┌──────────────────────────▼─────────────────────────────────┐
│                      API 层 (internal/api)                 │
│   路由注册 · 请求解析/校验 · 响应封装 · 中间件(日志/恢复/令牌) │
└──────────────────────────┬─────────────────────────────────┘
                           │ 方法调用
┌──────────────────────────▼─────────────────────────────────┐
│                   服务层 (internal/service)                │
│   审计服务 · 验证服务 · 归档服务 · 追溯服务（业务编排与规则）   │
└──────────────────────────┬─────────────────────────────────┘
                           │ 接口调用（Store 接口）
┌──────────────────────────▼─────────────────────────────────┐
│                    链核心 (internal/chain)                 │
│   哈希计算 · 链构造/追加 · 验证算法 · 密码学工具             │
└──────────────────────────┬─────────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────────┐
│             存储层 (internal/store) + 模型 (internal/model) │
│   SQLite 实现 · 迁移器 · 查询构建 · 条目/批次/验证结果模型    │
└────────────────────────────────────────────────────────────┘

  旁路：internal/worker（后台归档任务，通过服务层调用存储层）
        internal/server（HTTP 服务组装与生命周期）
        cmd/server/main.go（启动入口，装配全部依赖）
```

分层原则：**依赖只允许自上而下**，禁止反向引用；链核心不依赖存储实现（只依赖模型）；服务层依赖 `Store` 接口而非具体驱动，便于测试注入。

## 2. 技术选型

| 关注点 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Go 1.21+ | 并发原语、单二进制、交叉编译友好 |
| HTTP | 标准库 `net/http` | 零第三方依赖，路由规模小（13 个端点），手写路由足够 |
| 路由 | 自定义 `http.ServeMux` + 方法分发辅助函数 | 简单可控 |
| 数据库 | SQLite（`modernc.org/sqlite`） | 纯 Go、无 CGO、单文件、事务完备 |
| 哈希 | 标准库 `crypto/sha256` | 无需外部依赖 |
| 日志 | 标准库 `log/slog` | 结构化日志 |
| 配置 | 环境变量 + flag + 默认值 | 无配置文件解析依赖 |
| 前端 | 原生 HTML/CSS/JS + `embed.FS` | 简单、单二进制部署 |
| 测试 | 标准库 `testing` + `net/http/httptest` | 无第三方测试框架 |

## 3. 依赖方向与包边界

```
cmd/server        → internal/server, internal/config
internal/server   → internal/api, internal/worker, internal/config
internal/api      → internal/service, internal/model
internal/service  → internal/chain, internal/store(接口), internal/model
internal/worker   → internal/service, internal/config
internal/chain    → internal/model（只依赖模型，不依赖存储）
internal/store    → internal/model（含 SQLite 实现与迁移器）
internal/model    → 无内部依赖（纯数据结构 + 校验函数）
```

### 5.2 约束核对

| 约束 | 要求 | 规划值 | 结论 |
| --- | --- | --- | --- |
| Go 行数（不含测试） | > 2000 且 < 2200 | 2100（±50 允差） | ✅ 落在区间中部 |
| Go 文件数 | > 20 且 < 25 | 22 | ✅ |
| 前端 | 简单界面 | web/ 3 个静态文件 | ✅ 不计入 Go 行数 |
| 测试代码 | 不计入行数 | `*_test.go` 独立成文件 | ✅ |

> **实施说明**：行数预算是硬约束。编码时以本表为基准：若某文件实现超出预算，将注释收敛（少写说明性注释）或抽取辅助函数；若低于预算，补足该文件的校验分支/错误分支。最终以 `gofmt` 后的真实行数（`wc -l`，含空行、不含 `*_test.go`）验收，目标区间 2000–2200。

### 5.3 统计口径

- 计入：全部非 `_test.go` 的 `.go` 文件行数（含空行与注释，与 `wc -l` 一致）；
- 不计入：`*_test.go`、`go.mod`、`web/*`、`docs/*`、`README.md`；
- 若最终统计超出区间，调整策略见 5.2 实施说明（不允许删功能，只允许收敛注释/合并辅助函数；若低于 2000，则在 handlers 与 sqlite 中补充防御性分支与更完整的校验）。

## 6. 编码规范

1. **包名**：小写单数名词（`model`、`store`、`chain`、`service`、`api`、`worker`）；
2. **导出符号**：仅跨包需要的符号导出（`Entry`、`Store`、`NewServer` 等），其余小写；
3. **错误处理**：错误一律向上返回，不吞错；服务层包装错误上下文（`fmt.Errorf("append entry: %w", err)`）；
4. **日志**：`log/slog`，关键事件（写入、验证、归档、迁移、停机）打 Info，异常打 Error；
5. **常量集中**：哈希分隔符、默认配置、状态码字符串集中在各自的 `const` 块；
6. **禁止**：`panic`（除不可恢复错误）、`init()` 做业务初始化、全局可变状态（链头游标由 Store 持有）；
7. **注释**：导出符号必须有文档注释；注释简洁，避免占行（行数预算约束）。
